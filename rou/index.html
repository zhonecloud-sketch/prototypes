Google Drive setup

Enable the Google Drive API in your Google Cloud project. Configure the OAuth consent screen and a Web application client. Add this page's HTTP localhost or HTTPS origin as an authorized JavaScript origin. If the consent screen is in testing mode, add your Google account as a test user. Google sign-in does not run from file://. The app requests basic profile access and drive.appdata; no client secret is used.

Clock

Rounds follow the device clock in GMT+8.

Host synchronization uses uncached HTTP Date samples and half the round-trip time. HTTP Date has about one-second precision. If unavailable, use an accurate device clock. Clock changes are blocked while wagers are outstanding.

A seat at the table

Run the app

All application code, materials, wheel geometry, and sounds live in this HTML. Three.js is loaded from ../lib/three.module.js, then ../lib/three.module.min.js or ../lib/three.min.js, followed by pinned CDN fallbacks. No build step is required.

For local use, put this app and real.html in one folder. Put Three.js in a sibling lib folder. Serve their parent directory with python3 -m http.server 8000, then open the app at http://localhost:8000/your-folder/roulette.html. The tested engine version is Three.js r169. Its module file is standalone. Newer distributions may also require their companion core file.

The 30-second round

00–20: place wagers. 20–27: bets lock, the view moves down, and the ball spins. 27–30: the winning pocket is highlighted and returns are credited. Rounds use wall-clock slots, including after a background tab resumes. Each wagered round settles at most once; missed empty rounds are skipped. Joining during a locked round keeps the table visible until the next betting window.

Inside & outside bets

Click a number for a straight bet. Hover or focus the lines and intersections for splits and corners. The small dots below the number grid place streets; the gaps between those dots place six lines. On narrow screens, swipe horizontally within the table to reach every number; tap the chip stack to choose a denomination. Beside zero are zero splits, the two trios, and first four. Outside bets cover dozens, columns, color, parity, and low/high.

Winning returns include the original stake. Zero loses all even-money outside bets. French mode displays a racetrack in wheel order. Select a named sector or wheel number to preview its coverage and total cost, then press Place. Optional neighbours are straight bets on adjacent wheel numbers. Traditional called bets are: Voisins (9 units), Tiers (6), Orphelins (5), and Jeu zéro (4). It does not enable la partage or en prison. The displayed chip is one unit; called bets reserve their entire cost atomically. Tap the overlapping chip stack to reveal all 12 denominations, then select one to collapse the chooser.

Using a phone

Landscape is recommended for the wide betting table. Wide view requests fullscreen and landscape orientation when the browser supports it; portrait remains usable. Number cells keep at least 48 CSS pixels in each dimension, so smaller screens pan the table instead of shrinking it. On touchscreens, choose a bet type and tap a number; splits, streets, corners, and six lines open a large-target chooser. The bottom bar keeps your bankroll and session win/loss visible in either orientation, including during spins.

Recorded spins & timing

Real-life results are recorded data, played against GMT+8 time. No request is needed at spin time. A 20,160-row feed spans one week. Longer feeds continue from the anchored Sunday; shorter feeds have unavailable periods until repeat on a later Sunday. Source changes, feed replacement, and clock adjustment are blocked while wagers are outstanding. A source switch during a locked round takes effect next round. RNG uses unbiased rejection sampling from the browser's cryptographic pseudo-random generator.

Ball motion

The wheel and ivory-colored ball rotate in opposite directions, alternating each round. The seven-second spin uses 240 physics steps per second: rolling drag, radial descent, gravity, sphere contact against the actual brass deflector faces, and collisions against moving pocket frets. Each rotor pocket has a recessed floor and sloped inner, outer, and side walls; the ball rebounds from the same triangles used to render them, with friction and progressively damped impacts until it rests inside the pocket. Launches pass through the deflector ring; contact changes the ball velocity and creates a visible bounce. Payout occupies the final three seconds. The approach is guided toward the previously chosen or recorded pocket, then the ball enters a gravity-driven contact simulation for the final 1.9 seconds. The seven-second schedule determines presentation timing. This is a physics-inspired presentation of the outcome, not a physical outcome generator.

Bankroll & Google

Guest bankroll lives only in memory and starts at 1,000,000,000 play credits on each visit. Google sessions read and write a versioned JSON bankroll in the app's private Drive app-data folder. Outstanding wagers are included so a saved pending round can settle after reconnection. Tokens remain in memory. If permission expires or a save fails, a visible status asks you to reconnect or retry. Unsaved changes can be lost if you close the page. Use one active Google session at a time; revision checks reject conflicting saved sessions.

Client-side balances and preloaded real-life results are inspectable and editable. This standalone app is a play-credit simulation and is not a trusted real-money ledger.
